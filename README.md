# Melohum 音乐工作台

Cloudflare Worker 后端，Sites 托管 ChatGPT 登录，D1 按账户保存作品、音色、素材元数据、编曲和录音草稿、实验室设置及助手对话；R2 保存音频原件。公开浏览不需要登录，所有账户读写必须有 Sites 注入的身份。保留访客浏览器数据，可手动导入。

`npm test` 验证账户隔离、版本冲突、删除保护、上传限制及页面切换。`npm run build` 生成 dist/server 和 dist/client。D1 迁移保存在 drizzle，发布时自动应用。单条 JSON 记录上限 512 KB，单次 200 条，单个录音上限 25 MB。

已有网页六条分轨为 192 kbps MP3 试听副本，原始 FLAC 在 assets/stem-inputs。安装 numpy 和 soundfile==0.13.1（libsndfile 1.2.2），运行 python build-web-audio.py，可重建忽略的音频并校验哈希。然后 node check-site.mjs 校验资源与脚本。不要将用户数据、密钥或数据库备份提交到 Git。

AI 模型服务和任意歌曲的自动分轨需要独立的推理服务；此后端不虚构生成结果，也不包含模型密钥。

## 邮箱账户

邮箱账号与原有 ChatGPT 账户使用不同所有者 ID，不会凭相同邮箱自动合并。保留 ChatGPT 登录入口与旧作品。

新增邮箱注册、登录、找回密码。密码只能为 8–16 位 ASCII 字母数字，且必须同时包含两者；客户端和服务器共同校验。邮箱验证前不会创建用户。验证码 6 位，10 分钟有效，一次使用；错误最多 5 次。每个邮箱发信间隔 60 秒，每 IP 每小时最多 10 封，站点每日最多 500 封。登录尝试有邮箱和 IP 限流。

密码使用随机盐 scrypt（N=32768、r=8、p=3）；原密码不入库、不进日志。验证码只保存 HMAC；会话只保存令牌哈希，浏览器使用 HttpOnly / Secure / SameSite=Lax Cookie，7 天有效。重置密码会撤销该邮箱账户的所有会话。

生产环境需要在 Sites 的服务器环境变量中设置 `RESEND_API_KEY`（secret）、`AUTH_EMAIL_FROM`（已验证域名的发件地址），以及 `AUTH_CODE_SECRET`（secret，已生成）。不要把密钥放入前端、Git 或聊天。配置缺失会明确返回 503，禁用发码和注册，不会伪造邮件成功。修改环境变量后重新部署生效。Resend 验证域名必须由域名所有者完成；不使用个人邮箱连接器为网站代发验证码。

发信测试使用本地模拟服务；在设置真实发件地址和密钥后，仍需进行真实邮箱收件与跨设备登录验收。

## AI 可编辑成曲

服务端 `/api/assistant/song` 调用兼容 Chat Completions JSON 输出协议的模型，生成 16–64 小节、4–8 个角色分轨（必须含旋律、和声、低音、鼓），带完整连续段落与音符片段。前端展开片段为音符，接入现有编辑与播放系统。应用前明确提示替换当前编曲，保留撤销。此功能不是音频大模型的混音成品，也不自动完成母带制作。

模型需支持 `response_format: json_object` 与最多 14000 输出 token。公开站点不再直接暴露配置表单以外的密钥：所有者登录 `/ai-settings.html` 后设置代理 URL、模型名与 `MELOHUM_PROXY_TOKEN`。配置由服务端使用 `AI_CONFIG_ENCRYPTION_KEY` 经 AES-GCM 加密后保存到 D1；密钥不会回传给浏览器。`MELOHUM_ADMIN_EMAIL` 限定唯一管理账户。该页管理应用运行配置，不直接修改 Cloudflare 的部署环境变量。缺配置返回 503；在线模式不会降级成假 AI。需登录、同源请求，每账户每小时 10 次；音符数据有边界校验。真实模型、音乐质量和浏览器试听仍需配置后验收。
