# YIN 集成与识别修复

2026-11-16；修改前源码：996194dd1bfb8720b87413a7015f5c001aa67f47。

## 已修改

- 新录音的人声模式默认按连续音高变化切分，解决连唱A3→A4只输出A3的问题。保留用户显式选择的“每次发音一个音符”，模仿乐器模式仍默认按发音起点识别。v1旧浏览器偏好不再决定新默认；v2按人声/乐器分别保存。已保存作品的音符和识别选项不改写。
- `pitch-detector.js` 是独立纯模块：有限值/采样率校验、去直流、RMS、65–1200Hz范围、完整差分、CMNDF、首个可靠局部谷、回退最低候选、抛物线插值。保留候选及置信度。无可靠周期返回frequency=-1（原有兼容协议），后续转换为midi=null。
- 窗口化sinc低通用于降采样前抗混叠，分数延迟滤波系数缓存以控制开销。降到16kHz后逐样本计算差分，不再隔样本累积。
- 模糊八度候选仅在旧音高周期证据更强时短暂保留，连续三帧支持新音高后接受跳跃；高置信新音高直接接受。离线继续使用孤立尖峰清理，不强行把大音程折回。没有对所有音高做重度平均，保留滑音/颤音轨迹。
- 人声离线分析64ms窗、10ms步长；实时Analyser4096点，在44.1/48kHz约92.9/85.3ms。较长窗增加低音可检测性，也增加响应延迟；其余乐器profile原窗长保留。
- `pitch-worker.js`在后台Worker完成实时基频/候选跟踪和录音/上传的重采样、逐帧分析。`pitch-client.js`使用单个可复用Worker、单帧在途限流、超时/错误回退。页面仍通过现有Analyser采集，未引入AudioWorklet采集链重构。
- 实时检测最多约40次/秒（实际受rAF和计算影响），不排队积压；停止/重新录音通过generation丢弃迟到结果；时间戳减去半窗；无音高清除旧音名。最终轨迹继续以解码后的原音频为准。
- UI轨迹和音符切分各使用一次原始帧的孤立异常处理，避免串行重复平滑。编辑、播放、保存、导出、数据库和公开API未修改。

## 验证与复现

运行 `npm install`（依赖缺失时）、`npm run build`。

专项：`node --test tests/pitch-yin.test.mjs tests/pitch-baseline.test.mjs`。
旧基线数据：`node scripts/pitch-baseline.mjs`。
全套：`npm test`。

新算法测试含44.1/48kHz、C3/A3/C4/A4/C5、三档增益、二次泛音幅度为基音3倍、确定性噪声、E2低音、静音、DC、NaN、随机噪声、连续八度、同音重复、换气、80ms短音、滑音和5Hz±20cents颤音。200个稳定窗配置帧中，干净/强泛音最大误差0.457cents，含噪最大1.392cents，无八度错误。噪声设置及随机种子见测试源码；这些不是对所有噪声的保证。

Node VM下64ms窗口检测平均约10–13ms、P95约13–25ms（包含降采样；随运行机器变化），属于CPU基准，不是手机性能或端到端延迟。离线八度切换边界误差测试要求<60ms；无现场麦克风端到端延迟数据。

旧基线的3条测试包括对旧版丢音问题的刻画，应与新算法修复测试区分。全套原有两条AI成曲测试依旧失败（测试曲音符数量不满足现校验、旧系统提示大写字符串断言失效），未在本次音频任务中修改。

托管项目没有dev脚本，亦非静态hosting配置；sites-preview因此无法启动。本次本地浏览器麦克风/触屏与真实人声准确率尚未实测；构建和单元测试不代替听检。仓库没有有标注、授权用于本任务的真人哼唱评测样本。

## 使用

创作台选择“人声哼唱”，录音或上传单声部清唱；默认不勾选“每次发音一个音符”。旧作品若仍勾选该项，可关闭后点击重新解析，并保留撤销。新默认不自动重解析、覆盖旧作品。减少伴奏、混响、爆音有助于识别；复杂混音仍应走独立MuScriptor转写。

## 剩余限制

频率识别不等于节拍推断或复调转录。缺失基频、极弱基音、设备降噪、混音、周期性背景声仍会误判；短于分析窗口的音符和强颤音仍需实录评估。后台标签页rAF会降频，实时显示会变慢，MediaRecorder录音结束后仍重分析完整音频。Worker不可用时兼容回退在主线程执行，弱设备可能卡顿；并未声称所有浏览器都能无延迟。后续可实测AudioWorklet采集/专用Worker的持续PCM环形缓冲，但不将重DSP放在音频渲染线程。

创作台旧MIDI时间比例风险单独留待导出专项修复，本次没有变更其协议。
